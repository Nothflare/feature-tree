# Bootstrap Redesign - Phase 1 & 2

## Design Decisions

### 1. Unified Skill with Skippable Phases
- Single `/bootstrap` skill replaces current workflow-first approach
- Phase 1 (feature discovery) and Phase 2 (workflow identification) are both optional
- User can run Phase 1 only, skip to Phase 2 with manual guidance, or run both

### 2. Infrastructure Tracking
- **Already implemented** via `uses` field and `INFRA.*` naming convention
- No additional schema changes needed for infrastructure

### 3. Confidence Levels
- Add `confidence` field to features and workflows schema
- Values: `HIGH`, `MEDIUM`, `LOW`, or `null` (for manually created entries)
- Bootstrap-created entries always have explicit confidence
- Shown in search results when present

### 4. Synthesis Approach
- **Inline in orchestrator** — main Claude session handles merging/deduplication
- No separate synthesizer subagent
- Simpler, no extra dispatch overhead

### 5. Cross-Module Coordination
- Subagents include `cross_refs` section in their JSON output
- Orchestrator resolves cross-refs during synthesis
- No inter-agent messaging (Task tool doesn't support it)

### 6. Module Detection
- **Hybrid with user checkpoint**
- Quick directory scan to propose modules
- User confirms/adjusts before subagents are dispatched
- Prevents wasted work on wrong module boundaries

### 7. Phase Transitions
- **Explicit user choice** after Phase 1 completes
- Options: "Continue to Phase 2", "Review/edit features first", "Done for now"
- User has full control over the process

### 8. Bootstrap Log
- Auto-generated by the program (MCP tools), not written by agent
- Append-only during bootstrap session
- Lives at `.feat-tree/bootstrap-log.md`
- Timestamped entries for audit trail

## Phase 1 Flow: Feature Discovery

1. **Module Detection**
   - Scan directory structure, check config files
   - Propose modules to user for confirmation
   - User can add/remove/rename before proceeding

2. **Parallel Subagent Dispatch**
   - One Explore subagent per confirmed module
   - Subagents receive FT context (what features/infrastructure mean, confidence levels, naming conventions)
   - Each returns: features, infrastructure, cross_refs

3. **Inline Synthesis**
   - Merge duplicate features (same ID from multiple modules)
   - Process cross_refs to update `uses` relationships
   - Flag conflicts for user review

4. **Save to Database**
   - Create features with confidence levels
   - MCP tools auto-append to bootstrap-log.md

5. **User Checkpoint**
   - Show summary table with confidence and uses
   - Highlight LOW confidence and conflicts
   - User chooses: continue to Phase 2, review/edit, or done

---

## Phase 2 Flow: Workflow Identification

1. **Identify Terminal Features**
   - Find entry points (routes, handlers, commands)
   - Find leaf features (not used by others)
   - User confirms starting points

2. **Parallel Subagent Dispatch**
   - One subagent per terminal feature
   - Subagents receive list of known features (must map to existing IDs)
   - Each returns: trace of feature IDs, user outcome, confidence

3. **Further Investigation (Optional)**
   - Subagent traces are treated as "hints"
   - Orchestrator reviews for gaps (unclear paths, unmapped symbols)
   - Can investigate with user guidance before synthesis

4. **Synthesize Workflows**
   - Transform raw traces to clean flows
   - Collapse INFRA.* into parent features
   - Generate mermaid diagrams with feature IDs
   - Create workflows with confidence levels

5. **Coverage Check**
   - Verify every feature appears in at least one workflow
   - Uncovered features can become new starting points (loop back)
   - Or user can skip and add workflows manually later

6. **Journey Grouping (Optional)**
   - Single-agent pass to group related flows
   - Propose journey structure for user confirmation

---

## Subagent Context

Subagents must understand Feature Tree concepts:

- **FEATURE**: Atomic, user-facing capability ("implement X feature")
- **INFRASTRUCTURE**: Shared utilities, use `INFRA.*` prefix
- **Confidence**: HIGH (obvious), MEDIUM (reasonable inference), LOW (ambiguous)
- **cross_refs**: Flag dependencies on other modules for orchestrator to resolve
